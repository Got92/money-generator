# PR 09 — Valorisation historique

La migration additive v4 conserve chaque instantané obtenu lors d'une requête réussie à la fiche Yahoo dans une table indépendante des sauvegardes de portefeuilles. L'API `GET /api/valuation/history?symbol=...&asOf=AAAA-MM-JJ` retourne les multiples, observations, source, dates, devise, version de méthode et fiche source complète. Une lecture `asOf` exclut les instantanés récupérés après la date demandée. Les révisions intrajournalières sont conservées en base ; la dernière par jour alimente les statistiques. Les séries ne mélangent pas devises, sources ou versions de méthode. Les médianes 3/5/10 ans reflètent les observations effectivement collectées, et non une couverture supposée ; min, max, percentile de rang moyen, quartiles et nombre sont fournis. Le graphique utilise les quartiles et la médiane de la fenêtre sélectionnée.

Yahoo indique directement les PER TTM et forward, EV/EBITDA et Price/Sales. Les observations ne commencent qu'à la première consultation réelle. EV/EBIT, Price/FCF, EV/FCF et FCF Yield sont calculés lorsque quatre trimestres consécutifs, leur disponibilité à la date du cours et leur devise sont vérifiés ; leurs intrants sont conservés. Avec les métadonnées Yahoo historiques non vérifiées, ces valeurs restent indisponibles. Les résultats Yahoo peuvent être différés et les ratios publiés par le fournisseur ne détaillent pas intégralement leurs hypothèses. Les dates des séances et de récupération restent visibles. Les exports JSON de portefeuilles ne sauvegardent pas ces tables SQLite.

La calculatrice utilise des hypothèses saisies par l'utilisateur : multiple cible, montant financier total, actions diluées et, pour EV, dette nette signée. Elle prend aussi une médiane observée, un rendement FCF ou une décote sur la juste valeur. Les montants doivent partager devise et échelle ; aucun chiffre courant n'est réutilisé rétroactivement. Pour le PER forward, le montant est un bénéfice prévisionnel. Pour les PER TTM et forward, une médiane peut aussi être appliquée au BPA du dernier instantané lorsque sa devise financière correspond au cours ; source et dates sont affichées. Les autres hypothèses restent manuelles et la valeur est indicative.

Validation : tests unitaires Python (mathématiques, migrations, historique sans rétroactivité, endpoint avec fournisseur synthétique), JavaScript (calculs), suites existantes et navigateur Chromium sur la vraie navigation et l'API. Aucun accès à une base utilisateur. L'intégration future d'un fournisseur fournissant des versions financières datées et vérifiées pourra étendre la couverture sans rétroremplissage artificiel.
