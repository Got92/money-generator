# PR10 — Scénarios DCF persistants

Chaque symbole dispose de trois emplacements Bear, Base et Bull, créés uniquement à la saisie et indépendants. Les hypothèses sont des simulations manuelles, sans données financières préremplies. Le formulaire DCF historique reste disponible. Les projections utilisent cinq flux manuels, une croissance annuelle du flux initial, ou une croissance du chiffre d’affaires et une marge de flux de trésorerie disponible (pas une marge opérationnelle). FCFF utilise le WACC et déduit la dette nette ; FCFE utilise le coût des fonds propres et interdit une dette non nulle. Montants, actions et dette doivent être dans la même échelle et devise.

Les valeurs à un et cinq ans sont recalculées à partir des cinq flux suivant chacune de ces dates et d’une valeur terminale, avec croissance explicite après l’année cinq ; dette nette et actions sont supposées constantes. Le potentiel compare la valeur présente au cours actuel, seulement si les devises concordent. Le rendement annualisé du prix compare la valeur à cinq ans au cours actuel. Le rendement total cumulé inclut cinq dividendes annuels constants, non réinvestis, seulement si saisis. Cette distribution est une hypothèse additionnelle : l’utilisateur doit éviter de compter deux fois une trésorerie distribuée dans sa valeur future. Aucun rendement total n’est calculé sans dividende explicite.

`GET /api/valuation/scenarios?symbol=X` retourne `{symbol,scenarios,revision}` ; PUT enregistre un objet scénario avec cette `revision`, DELETE avec `name=Bear|Base|Bull` et `revision` supprime cet emplacement. Une révision périmée renvoie 409 ; rechargez avant de réessayer. Le serveur valide les champs financiers et préserve les champs additionnels JSON. Les modules purs exposent `projectScenario` et `evaluateScenario`. Les taux sont des fractions décimales dans l’API.

La migration additive v5 crée `valuation_scenarios`, sans clé étrangère vers les tables instantanées réécrites ; la sauvegarde de l’état ne la supprime pas. Migration transactionnelle et idempotente. Une restauration de la base sauvegardée avant migration est la méthode de retour arrière ; supprimer cette table ou sa version perdrait les scénarios enregistrés. Aucune migration descendante automatique n’est fournie.

Validation : 75 tests JavaScript, 42 tests Python avec base temporaire, et `TMPDIR=/workspace/work node scripts/check-scenarios-browser.mjs` (navigation réelle, sauvegarde, rechargement, contrôle API et suppression). Les projections sont des modèles sensibles aux hypothèses et ne constituent pas des cotations prévues.
